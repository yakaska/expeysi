# Модель данных и синхронизация

Источник правды для UI — локальная Room. Firestore хранит общий журнал изменений
семьи; оба телефона пишут туда свои изменения и слушают чужие. Офлайн-очередь и
доставку обеспечивает Firestore SDK.

## Идентификация и онбординг

- Вход — через Google Sign-In и Firebase Authentication. UID привязан к Google-
  аккаунту, поэтому сохраняется после переустановки и при смене устройства.
- «Семья» — это документ `families/{familyId}`. `familyId` — автогенерированный
  20-символьный ID Firestore, он же код приглашения: передаёшь код второму
  пользователю любым способом (мессенджер, из уст в уста).
- Присоединение: второй пользователь вводит код, приложение создаёт документ
  `families/{familyId}/members/{свой uid}`. Угадать чужой код перебором
  практически невозможно (20 символов, `[a-zA-Z0-9]`).
- Выход: пользователь удаляет свой документ `members/{uid}`, после чего приложение
  очищает локальные семейные данные. Google-аккаунт остаётся вошедшим, а семейный
  журнал сохраняется для остальных участников.

## Структура Firestore

```
families/{familyId}
  name: string                 # имя семьи, задаёт создатель
  createdAt: timestamp
  createdBy: uid

  members/{uid}
    displayName: string
    joinedAt: timestamp

  balances/{balanceId}         # UUID
    name: string               # "Основной", свой вариант
    currencyCode: string       # ISO 4217: "RUB", "USD", ...
    deleted: boolean
    updatedAt: long                # epoch millis для LWW

  accounts/{accountId}         # UUID
    name: string               # "Наличные", "Карта", свой вариант
    iconKey: string
    colorKey: string           # ключ цвета обода иконки из общей палитры
    openingBalanceMinor: long  # начальный остаток в минимальных единицах валюты баланса
    balanceId: string          # баланс, к которому относится счёт; валюта счёта = валюта баланса
    deleted: boolean
    updatedAt: long                # epoch millis для LWW

  categories/{categoryId}      # UUID
    name: string
    iconKey: string            # ключ из фиксированного набора Material Icons
    colorKey: string           # ключ цвета обода иконки из фиксированной палитры
    type: "income" | "expense"
    deleted: boolean
    updatedAt: long                # epoch millis для LWW

  transactions/{transactionId} # UUID
    type: "income" | "expense"
    amountMinor: long          # сумма в минимальных единицах валюты счёта
    accountId: string
    categoryId: string
    date: long                 # epoch millis (локальная дата автора)
    note: string               # может быть пустой
    deleted: boolean
    updatedAt: long                # epoch millis для LWW
    updatedBy: uid
```

Справочник валют (ISO 4217, ~230 записей: код, английское название, символ)
живёт только локально в Room (`currencies`), загружается миграцией и посевом при
создании БД. В Firestore не синхронизируется: список одинаковый на всех
устройствах. Упрощение MVP: у всех валют два знака после запятой, даже у
безразрядных вроде JPY.

Балансы группируют счета и задают им валюту: у баланса есть `currencyCode`,
счёт ссылается на баланс через `balanceId`. На главном экране показывается
выбранный баланс (выбор хранится локально на устройстве) и суммы по его счетам
за скользящие окна: сегодня, последние 7 дней, последние 30 дней.

## Предзаписанные данные

Категории и счета по умолчанию имеют детерминированные UUID (константы в коде),
одинаковые на всех устройствах. Сидируются в Room при первом запуске и в Firestore
при создании семьи — повторная запись с тем же ID ничего не дублирует.

Счета по умолчанию: «Наличные», «Карта».
Категории расходов: продукты, транспорт, жильё, кафе, здоровье, развлечения, прочее.
Категории доходов: зарплата, подработка, прочее.
(Точный список и UUID — в коде приложения, этап «Android: данные».)

## Правила слияния

- Каждое локальное изменение (создание/правка/мягкое удаление) пишется в Firestore
  документом с тем же UUID и свежим `updatedAt`.
- При получении чужой версии документа: если её `updatedAt` новее локальной —
  перезаписываем локальную (last-write-wins). Равенство игнорим, локальную более
  новую версию отправляем в Firestore.
- После первого снимка realtime-слушателей локальные документы сверяются с ним по
  UUID и `updatedAt`. Полной перезаписи базы при запуске нет: отправляются только
  отсутствующие в Firestore или локально более новые документы. Неизменившееся
  содержимое повторно не пишется: метка времени и автор правки не считаются
  содержимым (иначе переустановка, сиды и расхождение часов гоняли бы пачки
  холостых записей).
- Отключение и повторное подключение realtime-слушателя идёт с растущей паузой
  (5 с, 10 с, 20 с… до 5 мин); `PERMISSION_DENIED` повторов не запускает:
  членство в семье снято сервером, и гонять полные снимки впустую не нужно.
- Сессия семьи поднимается, только когда есть и семья, и вход: восстановление
  Firebase-сессии асинхронно, и запуск синхронизации ждёт его.
- Слушатели снимка стоят, только пока приложение видно пользователю: после ухода
  в фон даётся 10 минут на быстрое возвращение, дальше слушатели снимаются и
  поднимаются на следующем показе экрана. Офлайн-кэш Firestore и Room от этого
  не страдают; телефон в кармане не получает платные realtime-чтения без
  смотрящего экрана.
- Импорт CSV атомарно записывает данные в Room пачками, затем отправляет их в
  Firestore через `WriteBatch` группами не более 500 документов.
- Удаление мягкое: `deleted = true`, запись продолжает синхронизироваться и
  участвовать в LWW. Физическая чистка — отдельная история, в MVP не делаем.
- Баланс счёта всегда вычисляется: `openingBalanceMinor + доходы − расходы`
  по неудалённым операциям счёта.

## CSV-экспорт и round-trip

Экспорт выгружает один файл в формате импорта «Бюджета» (`Дата;Время;Название
счета;Категория;Сумма;Валюта;Комментарий`, разделитель `;`, UTF-8 с BOM) и
возвращается в приложение через «Импорт из Бюджета» — round-trip сходится.
В экране экспорта выбираются типы операций: доходы и/или расходы; служебные
строки и начальные остатки выгружаются всегда.

- Начальный остаток счёта идёт служебной строкой с зарезервированной категорией
  «Начальный остаток»: положительный остаток — доход, отрицательный — расход.
  Импорт распознаёт такие строки и ставит счёту `openingBalanceMinor` вместо
  создания операции; категория под это имя не создаётся. Имя зарезервировано
  в редакторе категорий, иначе операции пользователя в такой категории при
  переимпорте превратились бы в остатки.
- После «Комментарий» идут опциональные колонки оформления (только в файлах
  Expeysi; файлы «Бюджета» их не содержат): «Иконка категории», «Цвет категории»,
  «Иконка счета», «Цвет счета», «Название баланса», «Иконка баланса»,
  «Цвет баланса». Значения дублируются на каждой строке счёта, включая служебные:
  при потере части строк атрибуты уцелевают. Пустое значение — дефолт.
- Импорт аддитивен и всегда разрешён: балансы и счета всегда создаются новыми,
  существующие не переиспользуются и не изменяются — данные файла ложатся
  отдельной копией рядом с текущими, а неудачный импорт убирается целиком
  удалением нового баланса. Повторная загрузка того же файла тоже разрешена и
  кладёт ещё одну копию; никакой блокировки по «уже импортировано» нет. Импорт
  обновлённого экспорта создаёт полную копию (старые операции вместе с новыми).
- Копии балансов при импорте получают префикс «импорт » (строка данных в коде
  импортёра, как «Бюджет (валюта)»); если имя «импорт Base» занято — номер
  в скобках за максимальным занятым активным: «импорт Dong», «импорт Dong (2)»,
  «импорт Dong (3)»… Баланс без названия — автосозданный «Бюджет (валюта)»,
  как у файлов внешнего «Бюджета». Счёт группируется по тройке (имя, валюта,
  баланс): одноимённые счета разных балансов не сливаются.
- Импорт при создании сущностей берет оформление из первой строки, где сущность
  встретилась: новый баланс/счёт получает иконку и цвет из файла. Категория —
  общая на приложение: при импорте она переиспользуется по паре (нормализованное
  имя, тип) для привязки операций, иначе список категорий засорялся бы дубликатами.
  Явные иконка и цвет в строке — признак файла экспорта Expeysi: они перекрашивают
  существующую категорию, поднимая `updatedAt` для LWW. Файлы внешнего «Бюджета»
  таких колонок не пишут и оформление категорий не меняют.
- Валюта счёта — валюта его баланса: в `accounts.currencyCode` живёт резервный
  дефолт, экспорт и импорт не полагаются на неё.
- Экспортируются все активные счета и их активные операции выбранных типов;
  порядок счетов в служебных строках — по имени, операций — по дате. Дата и
  время в колонках — настенные (локальный часовой пояс телефона): при экспорте
  и импорте в одной зоне round-trip точен.
- Загрузка импорта в Firestore не блокирует его навсегда: подтверждение батча
  ждётся с таймаутом, после истечения записи остаются в офлайн-очереди Firestore
  и доставляются сами.
- Ограничения: удалённые записи не экспортируются; счёт с нулевым остатком и
  без операций не экспортируется. Из существующих сущностей при импорте меняются
  только категории (перекраска файлами экспорта Expeysi, см. выше). Операции не
  дедуплицируются: каждая загрузка кладёт полную копию операций файла в её новые
  балансы; ненужная копия удаляется целиком вместе с балансом.

## Даты и периоды

- День и месяц — по локальному часовому поясу телефона, неделя — с понедельника.
- Виджеты считают суммы по неудалённым операциям за текущие день/неделю/месяц.
