# Модель данных и синхронизация

Источник правды для UI — локальная Room. Firestore хранит общий журнал изменений
семьи; оба телефона пишут туда свои изменения и слушают чужие. Офлайн-очередь и
доставку обеспечивает Firestore SDK.

## Идентификация и онбординг

- Вход — анонимная Firebase Authentication (без аккаунтов и паролей). uid
  привязан к установке приложения: при переустановке пользователь заново
  присоединяется к семье по коду.
- «Семья» — это документ `families/{familyId}`. `familyId` — автогенерированный
  20-символьный ID Firestore, он же код приглашения: передаёшь код второму
  пользователю любым способом (мессенджер, из уст в уста).
- Присоединение: второй пользователь вводит код, приложение создаёт документ
  `families/{familyId}/members/{свой uid}`. Угадать чужой код перебором
  практически невозможно (20 символов, `[a-zA-Z0-9]`).

## Структура Firestore

```
families/{familyId}
  name: string                 # имя семьи, задаёт создатель
  createdAt: timestamp
  createdBy: uid

  members/{uid}
    displayName: string
    joinedAt: timestamp

  balances/{balanceId}         # UUID
    name: string               # "Основной", свой вариант
    currencyCode: string       # ISO 4217: "RUB", "USD", ...
    deleted: boolean
    updatedAt: timestamp

  accounts/{accountId}         # UUID
    name: string               # "Наличные", "Карта", свой вариант
    iconKey: string
    openingBalanceMinor: long  # начальный остаток в минимальных единицах валюты баланса
    balanceId: string          # баланс, к которому относится счёт; валюта счёта = валюта баланса
    deleted: boolean
    updatedAt: timestamp

  categories/{categoryId}      # UUID
    name: string
    iconKey: string            # ключ из фиксированного набора Material Icons
    colorKey: string           # ключ цвета обода иконки из фиксированной палитры
    type: "income" | "expense"
    deleted: boolean
    updatedAt: timestamp

  transactions/{transactionId} # UUID
    type: "income" | "expense"
    amountMinor: long          # сумма в минимальных единицах валюты счёта
    accountId: string
    categoryId: string
    date: timestamp            # день операции (локальная дата автора)
    note: string               # может быть пустой
    deleted: boolean
    updatedAt: timestamp
    updatedBy: uid
```

Справочник валют (ISO 4217, ~230 записей: код, английское название, символ)
живёт только локально в Room (`currencies`), загружается миграцией и посевом при
создании БД. В Firestore не синхронизируется: список одинаковый на всех
устройствах. Упрощение MVP: у всех валют два знака после запятой, даже у
безразрядных вроде JPY.

Балансы группируют счета и задают им валюту: у баланса есть `currencyCode`,
счёт ссылается на баланс через `balanceId`. На главном экране показывается
выбранный баланс (выбор хранится локально на устройстве) и суммы по его счетам
за скользящие окна: сегодня, последние 7 дней, последние 30 дней.

## Предзаписанные данные

Категории и счета по умолчанию имеют детерминированные UUID (константы в коде),
одинаковые на всех устройствах. Сидируются в Room при первом запуске и в Firestore
при создании семьи — повторная запись с тем же ID ничего не дублирует.

Счета по умолчанию: «Наличные», «Карта».
Категории расходов: продукты, транспорт, жильё, кафе, здоровье, развлечения, прочее.
Категории доходов: зарплата, подработка, прочее.
(Точный список и UUID — в коде приложения, этап «Android: данные».)

## Правила слияния

- Каждое локальное изменение (создание/правка/мягкое удаление) пишется в Firestore
  документом с тем же UUID и свежим `updatedAt`.
- При получении чужой версии документа: если её `updatedAt` новее локальной —
  перезаписываем локальную (last-write-wins). Равенство и старая версия — игнорим.
- Удаление мягкое: `deleted = true`, запись продолжает синхронизироваться и
  участвовать в LWW. Физическая чистка — отдельная история, в MVP не делаем.
- Баланс счёта всегда вычисляется: `openingBalanceMinor + доходы − расходы`
  по неудалённым операциям счёта.

## Даты и периоды

- День и месяц — по локальному часовому поясу телефона, неделя — с понедельника.
- Виджеты считают суммы по неудалённым операциям за текущие день/неделю/месяц.
