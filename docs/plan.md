Порядок: репозиторий, Firebase-проект, Android без сети, синхронизация, релиз,
анимации. К следующему этапу переходим только после выполнения условия
готовности предыдущего.

## Решения, зафиксированные сразу

- Синхронизация — Firebase Firestore, без своего сервера. Офлайн-кэш и очередь
  записей даёт сам SDK; realtime-слушатели дают почти мгновенную доставку изменений.
- Room на телефоне остаётся источником правды для UI, Firestore хранит общий журнал
  изменений семьи.
- id записей — UUID, суммы — Long в минимальных единицах валюты (копейки).
  Баланс не хранится, а считается: начальный остаток счёта + доходы − расходы.
  Баланс задаёт валюту, счёт наследует её от баланса (код ISO 4217).
- Удаление мягкое (флаг `deleted`). Конфликт версий решает last-write-wins по
  `updatedAt` — метке времени, которую ставит устройство, сделавшее правку.
- Предзаписанные категории, счета и баланс («Основной») получают одинаковые
  детерминированные UUID на всех телефонах, поэтому дубликатов после синка нет.
- Иконки хранятся ключами-строками: `iconKey` — из фиксированного набора
  Material Icons (неизвестный ключ рисуется иконкой по умолчанию),
  `colorKey` — цвет обода иконки из общей палитры.
- Неделя считается с понедельника, день и месяц — по локальному часовому поясу телефона.

Полную модель данных, схему Firestore и правила слияния — см. `docs/data-model.md`.

## Отклонённые варианты синхронизации

- Свой сервер (Spring Boot + VPS): деплой, бэкапы, поддержка — избыточно для двух
  пользователей.
- Bluetooth / Nearby Connections: синхронизация только когда телефоны рядом и
  приложение открыто, конфликты всё равно пришлось бы разруливать вручную.
- Supabase: рабочая альтернатива Firebase, но для Android realtime и офлайн-кэш
  у Firebase зрелее.
- Google Drive appDataFolder: нет realtime, нужен общий Google-аккаунт.
